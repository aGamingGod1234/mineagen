# #54 Keep boat batch machines running and reuse them instead of starting new ones

- **Problem:** Every batch of practice rooms started fresh cloud machines and deleted them when it finished. The cloud provider limits how many machines can be started per minute, hour and day, so parallel test threads ran out of starts while most of the paid compute sat unused. A batch also held every room until its slowest machine was ready.
- **Solution:** A warm pool. Batches lease machines that are already running, clean them between batches (kill leftover game servers, wipe the old batch's files, keep the image), and give them back running. Lock files with heartbeats keep two batches off one machine. New machines are started only for a shortfall, paced under the limits. Each machine starts playing rooms the moment it is ready.
- **Result:** Measured on six back-to-back one-room batches on one machine: 1 machine start in all, against 6 before (one per batch per machine), and 0 machines deleted. Every room on the reused machine passed, including the one right after a batch stopped mid-room. A warm machine went from lease to a playing room in about 7 s, with cleaning taking about 1 s of that. Estimated: a pool of N machines serves any number of batches for N starts while it is kept warm.
