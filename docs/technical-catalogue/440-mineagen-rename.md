# PR #440: Rename the project to Mineagen and rewrite the README for players

- **Problem:** The project name sat in 1,239 of 2,500 tracked files: 7,641 lines across the mod id, the Java package, 1,013 file paths, jar and folder names, one command and the JVM properties. A search-and-replace in a working tree also rewrites line endings (one tracked file already differs from its committed bytes on checkout), and 22 open branches still use the old name.
- **Solution:** A script reads the committed bytes of every file from Git, applies 15 ordered substitutions to contents and paths, writes the new blobs and tree directly, and makes one commit. The working tree is never the source, so line endings and unstaged edits cannot leak in. Binary files only move. Five strings are kept on purpose: the scoreboard team name that old worlds carry, another repository's name, two test paths that need a space, the private repository's own name, and the wider `arena` prefix (ArenaScript, `ARENA_*` variables), which the model reads in its prompt. The script reruns on any older branch.
- **Result:** One commit, 1,149 files edited and 1,013 moved, with equal insertions and deletions (7,641 each). The three Minecraft targets build, the coordinator suite passes 8,040 tests with the private archive and 7,869 without, and the public copy passes its own 7,850, all with zero failures. The only follow-up the checks asked for was two line hashes in the public-tree exemptions. Of four parked game branches, two trial-merge with no conflicts and two with 6 each.
